### Task 1: Seam — committed command writes, in order (#557)

`OnEntriesWritten` coalesces by address and tells one actor job later that an entry changed; an application reads the latest value only. A command word needs every committed value.

**Interfaces — produces:**

```csharp
// ICanOpenApplication
IReadOnlyList<CanOpenObjectAddress> CommandEntries { get; }          // claimed entries whose every committed write is delivered; default: empty
void OnCommandWritten(CanOpenObjectAddress entry, byte[] value);      // actor loop, one call per committed write, in commit order
```

Rules: a command entry must lie in the application's claims and be at most 8 bytes (else the open fails, ParamName `"options"`). Each committed write (SDO, RPDO, local) of a command entry is queued with a copy of its value and delivered in commit order, before the coalesced `OnEntriesWritten` of the same actor turn; the entry is **not** additionally reported through `OnEntriesWritten`. A refused write (validator, access, size) is never delivered. The application's own writes are not delivered (the seam's own-write rule). The queue is bounded (256 per node): when it is full, the write is refused — over SDO with abort `0800 0022h` (present device state), an RPDO entry is dropped as the node drops any refused RPDO entry — so nothing is lost silently and the mailbox cannot grow without bound; the doc says so. Reset drops what is queued. `Cia401Device` gets the empty default.

Tests (seam, recording application): the #557 reproduction — `0009h` then `0001h` committed before the actor drains → two calls, in order, values as written; a refused write → no call; SDO and RPDO and local writes interleaved keep commit order; own write not delivered; full queue → SDO abort `0800 0022h`, nothing delivered for it, earlier ones intact; ordering against `OnEntriesWritten` for a batch containing a command entry and an ordinary one; dispose mid-queue; a command entry outside the claims fails the open.

- [ ] Tests red, implement, mutations (deliver the latest value twice; drop the bound; deliver before commit), commit `refactor(canopen): deliver committed command writes to an application in order`.

### Task 7: The state machine, pure

`Cia408StateMachine` — no node, no dictionary: state in, event in, state and actions out.

```csharp
internal enum Cia408State { NotReady, Init, Disabled, Hold, Active, FaultInit, FaultDisabled, FaultHold, FaultReaction }
internal enum Cia408FaultState { FaultInit, FaultDisabled, FaultHold }
internal sealed class Cia408StateMachine
{
    Cia408State State { get; }
    IReadOnlyList<int> Start();                                             // D0, D1 → Init
    IReadOnlyList<int> ApplyControlWord(uint previous, uint current);       // the D-numbers taken, in order
    IReadOnlyList<int> Fault(Cia408FaultState requested);                   // D8, then D9 / D12 / D13 within Table 9's limits
    IReadOnlyList<int> Restart();                                           // D255, D0, D1
    static byte StatusBits(Cia408State state);                              // RMHD, Table 4
}
```

Readings (each stated in the XML doc with the passages; the norm is silent or contradictory on all of them):

- **A control word is followed to the stable state**: `0111b` in INIT takes D2, D3, D4 and ends in ACTIVE; `0000b` in ACTIVE takes D5, D6, D7. Tables 7/8 give per-transition conditions, not steps per write.
- **Fault reset is a change between two words, read strictly as Table 7 writes it** (as built): the previous word has bits 2..0 at the fault state's own pattern with R (bit 3) = 0, the written word the same pattern with R = 1 — D10 `0001b` → `1001b`, D11 `0011b` → `1011b`, D14 `0000b` → `1000b`. A rising bit 3 with any other pattern on either side does not reset (FAULT_HOLD with `0000b` then `1011b` stays), and bit 3 held at 1 does nothing in a fault state. The reset is judged once, in the state the write arrives in, before any level transition, never after a fall within the fault states in the same write (`0001b` then `1001b` in FAULT_HOLD takes D15 only). After a reset the written word is followed on as above; it carries the pattern of the state it leads to, so it never moves further (`1011b` after D11 stays in HOLD; bit 2 would be needed for ACTIVE).
- **Down within the fault states** by level: D15 (`x001b` in FAULT_HOLD), D16 (`x000b` in FAULT_DISABLED).
- **Leaving FAULT_REACTION is the device's decision** (Table 4, Table 9), not the control word's (Tables 7/8 list patterns for D12/D13 and Table 8 alone lists D9): `Fault(requested)` clamps the request to what Table 9 allows from the state the fault came from, and takes D9, D12 or D13 at once. FAULT_REACTION is never a resting state of this device.
- **A fault in a fault state** (D8 from FAULT_*) re-evaluates within Table 9 and never moves up.
- NOT_READY has no status encoding in the norm; `StatusBits` gives `0000b` and the doc says so.
- Table 8 (hardware enable signal) is not built in this slice.

Tests (Review Focus 4): a table of all 9 states × 16 values of bits 3..0, each with the previous bit 3 at 0 and at 1, expected successor and expected D-list written out in the test; the cascades; every row of Table 9 for every requested fault state; `Restart` from every state; `StatusBits` for every state.

- [ ] Tests red, implement, mutations (reset by level instead of edge; one step instead of the cascade; Table 9 not clamped; D15/D16 swapped), commit `refactor(canopen): add the CiA 408 device state machine`.

### Task 9: Device — NMT coupling, reset

§7.8 Table 10, Figure 2 and Table 6 disagree with each other (the digest of the norm lists it): Table 10 sends a reset of the application "to INIT … and D13", Figure 2 draws FAULT_INIT, Table 6 says leave (D255) and restart (D0, D1).

### Task 10: Device — modes, setpoints, actual values, the process model

```csharp
internal interface ICia408Process
{
    // Called on the actor loop every Cia408Configuration.ProcessInterval of the node's clock, and once after every state change.
    void Step(Cia408ProcessContext context);
}
internal sealed class Cia408ProcessContext   // state, device mode, control mode, elapsed time since the last step; Setpoint(definition) reads; SetActual(definition, value) / SetStatusBit(bit, on) write
```

- `6042h` device mode: values the configuration supports, else value-range abort; a write in ACTIVE is refused (Table 4) with `0800 0022h`; read-only if the configuration has one device mode (§9.3.4, Table 81, footnote a). `6043h` control mode: supported values; changeable only in INIT, DISABLED, FAULT_INIT, FAULT_DISABLED (Table 5), else `0800 0022h`; read-only if the configuration has one mode (§9.3.5). The default PDO mapping follows the default control mode only — a mode change does not remap PDOs (the norm does not ask for it); documented.
- For each supported control mode a configured device declares, in the mode's width, the setpoint and actual value records its mappings name (Tables 13, 31, 32) and those clause 9 makes mandatory with it (`Cia408DeviceProcessTests.Each_Control_Mode_Declares_The_Records_The_Norm_Gives_It` holds the table), as value records with the catalogue's unit and prefix; a device from a description requires only the clause-9 ones and adopts the others where the file declares them; which setpoint is effective in which state is the model's business — the context tells it the state (HOLD: hold setpoint; ACTIVE: device-mode setpoint, Table 5).

## Decisions this plan makes

All internal, all changeable until publication; none was the maintainer's except where an issue is cited.

- **Seam changes come from the maintainer's issues**: ordered command writes (#557), RPDO reception with TPDO by number (#558), the `1029h` layout (#559).
- **A control word is followed to the stable state** (cascade), not one transition per write.
- **The device, not the control word, chooses the fault state** when leaving FAULT_REACTION, within Table 9; FAULT_REACTION is never a resting state.
- **A fault reset is refused while a cause is still active.**
- **NMT Stopped, Reset Communication and a communication failure force a fault state without an EMCY**; Reset Node / Reset Application restart the machine (Table 6 over Table 10 and Figure 2).
- **Both control/status word pairs exist and are one state**, although a device has one resolution.
- **Default PDO 1 = mapping 1, PDO 2 = the default control mode's mapping**, CiA 301 COB-IDs, valid, type 255; a control-mode change does not remap.
- **NMT slave only**; no "virtual device application manager".
- **Not built in this slice**: the hardware enable signal (Table 8), the controllers and conditioning blocks of clauses 9.5–9.49 (objects are in the catalogue and readable through the peer; the device declares only §9.3 and the setpoint/actual objects of its control modes), the mode-specific meaning of control/status bits 7–11 (stored and handed on), parameter-set switching (bits 6–7).
- **The catalogue is a hand-checked data table**, made with two machine extractions kept outside the repository; `63D8h`, the two mis-indexed tables, `6280h` and `6780h`/`6781h` as ruled in Task 5.
- **No commit of type `feat`.**

### Decided while building

Rulings made during Tasks 1–13, each documented at the code it governs (the task reports in the SDD directory give the arguments; the code is the authority where they differ).

- **Fault reset strictly as Table 7 writes it** (Task 7 above), judged once at the arrival state.
- **Command writes and resets**: under Reset Communication the queued command writes are kept and delivered after the reset's notifications; under Reset Node they are dropped, which also frees the queue for writes made after the restore. `604Fh` is a command entry, so the source of the control word is followed in commit order with the words.
- **Two TPDOs for a state-changing RPDO**: the change-driven one and the §8.4.1 answer. The device cannot tell an RPDO's command write from an SDO one, and the norm forbids neither; an inhibit time delays the answer.
- **The device mode is not changeable in ACTIVE (Tables 4 and 5), HOLD and FAULT_HOLD**, the last two this device's choice within Table 5's manufacturer-specific cells, resting on D5 and D9 of Table 6. The control mode changes in INIT, DISABLED, FAULT_INIT and FAULT_DISABLED only (Table 5). The state judged is the one at commit time.
- **Warnings survive Reset Node**; `604Eh` keeps the code of the warning or fault that occurred last; fault codes `0001h`–`00FFh` (class "error reset or no error") are refused.
- **Table 10 applies from every resting state** (Figure 2 over the sentence naming a state the machine does not have); a communication failure forces the fault reaction and is a cause while it lasts; Reset Node re-enters the faults the application still reports.
- **The `1029h` layout** is the profile's: a node with CiA 401 (no layout) and CiA 408 has CiA 408's record; a description's `1029h` must declare every class the layout names.
- **"ir" is unit `00h`**, unit and prefix are read-only on the device, records are declared per supported mode in that mode's width, the default process interval is the one `Cia408Configuration.DefaultProcessInterval` states, and a throwing process model is contained.
- **The tool side's wait**: one Table 7 transition per write; after each write the status is read up to `Cia408PeerOptions.StatusReads` times with `StatusPause` between reads, on a delay the caller may put on its own clock; a failure is a `Cia408CommandException` whose reason says local control, fault state, not reached or no fault, and leaves the last control word in the device. A status with R = 0 that is no fault state's pattern reads as FAULT_REACTION (Figure 1 over Table 4) and is read through.
- **The word pair** follows one rule on both sides (`Cia408Configuration.IsWide`): a drive mode is 32 bit, a valve mode 32 bit only on dtprs 10b; where the modes of an 11b device differ, the tool reads `6043h`. The drive bits of a 16-bit device type are "do not care" (Table 53 NOTE 1) and are skipped.
- **A device from an EDS/DCF**: the file wins; the 16-bit pair and `6042h` are mandatory, the 32-bit pair whenever the resolution (the file's, or the one the objects give) is 10b or 11b, and half a pair fails the open; bits 23/24 are split by the closed-loop actual value; optional objects the file leaves out are not added and behave as their defaults; what shows the device's state is the device's from the start.
