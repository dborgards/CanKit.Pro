# EN 50325-5:2010 against `CanKit.Pro.CANopen` — 2026-11-04

The comparison #289 asks for: the defaults, value ranges and sub-indices of `1301h`–`1340h`, `1381h`–`13C0h` and `13FEh`, row by row, against the text of the standard (DIN EN 50325-5:2016-06, English version of EN 50325-5:2010). The neighbouring objects and the rest of the text were read alongside; those results are in [Beyond the three objects](#beyond-the-three-objects).

The standard is copyrighted and not in this repository: this file gives clause, table and value, not its wording. It is a dated record of a comparison of the protocol objects. It claims no safety integrity level and no conformance statement under clause 11 of the standard, which needs far more than this library provides.

Result words: **conform**; **fixed** (a deviation closed by the pull request this file arrives with); **narrower** (a value the standard allows is refused, permitted or kept as stated); **wider** (a value outside the range is accepted, kept as stated).

## `1301h`–`1340h`, SRDO communication parameter (Tables 3, 4, 5)

Access in every row but `00h` and `04h`: `ro` in Operational, `rw` in Pre-operational — see [Bus access](#bus-access).

| Sub | Standard | Implementation | Result |
| --- | --- | --- | --- |
| `00h` | `ro`, value and default 06h | `ro`, 6; a write `0601 0002h` | conform |
| `01h` | 00h, 01h, 02h; 03h..FFh reserved. Default: SRDO 1 of node-id 1..32 01h, 33..64 02h, 65..127 00h; other SRDOs 00h | The same; 3..255 `0609 0030h` | conform (since #398) |
| `02h` | UNSIGNED16, and n > 0 for producer and consumer (§6.2.1). Default tx 25, rx 50 | 1..65535. Default was 25 in every record | **fixed**: SRDO 1 of a node-id 33..64 now holds 50, also after an LSS change across 32/33. A record with direction 00h has neither default in the table; it holds 25 |
| `03h` | Rx: SRVT, n > 0 (§6.2.1). Tx: reserved. UNSIGNED8, default 20 | 1..255 in both directions, default 20 | conform for rx. **Narrower** for tx: 0 is refused on a reserved field. Kept: the record's direction is written last, so the write cannot tell, and a tool has no reason to write a reserved field |
| `04h` | `ro`, value and default 254 | `ro`, 254. On the bus a write gets `0601 0002h`, locally `0609 0030h` | conform. The README said `0609 0030h` for every write, which held only locally; corrected |
| `05h` | 257..383, odd. Default SRDO 1: 00FFh + 2 × node-id up to node-id 64, otherwise manufacturer-specific | 101h..17Fh odd, or 0. The same default; manufacturer-specific is 0 | **Wider**: 0 is accepted while the SRDO is deleted and is the manufacturer-specific power-on value. Kept by maintainer decision: it means "not set", an SRDO cannot be created with it, and it never reaches the bus |
| `06h` | 258..384, even, the number after `05h` (§6.4.1.3). Default SRDO 1: 0100h + 2 × node-id up to node-id 64, otherwise manufacturer-specific | 102h..180h even and COB-ID 1 + 1, or 0. The same default | as `05h` |

Refusing a COB-ID change while the SRDO exists is V1.0's rule; Table 5 does not state it. **Narrower**, kept: V1.0 stands where this text is silent.

## Bus access

Tables 5, 8, 11 and 13 give `rw` in Pre-operational and `ro` in Operational, Table 15 `rw` for `1300h`, and §8.1 has the connections set up by SDO download. V1.0's footnote that the entries may be read-only does not appear there; §8.2.2 says read/write "if supported".

Without `WritableCommunicationParameters` the node had all of them `ro` on the bus, so a tool working to the standard got `0601 0002h` — also on `13FFh:n`, contrary to the maintainer's note of 2026-10-23 on #289.

**Fixed** by maintainer decision: read/write without an option, Operational refused by the validator as before (`0800 0022h`, `1300h` excepted). The option remains for the PDO records. A device description may still declare less.
